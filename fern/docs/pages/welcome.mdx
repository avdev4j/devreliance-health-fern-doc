**DevReliance Health** is the documentation surface for `healthcare-org` — a canonical demo platform maintained by the Postman Developer Relations team, with source at [github.com/healthcare-org-app](https://github.com/healthcare-org-app).

It models a hospital group's software estate the way one actually looks: **101 independently-deployable services** across fourteen business domains, talking over HTTP and Kafka, each owning its own database, plus event-driven integration into an external ERP owned by a different organization.

The point is the scale and the mess that comes with it. Most API examples are one service with five endpoints, where every problem worth demonstrating has already been designed away. This one has 285 declared service-to-service dependencies and 107 event subscriptions, so questions like *which teams break if this response shape changes* have answers you have to go and find.

## By the numbers

| | |
|---|---|
| Services | **101**, each independently deployable |
| Repositories | **104** — 101 services + 3 meta repos |
| Business domains | **14** |
| Languages | Python (94), Go (4), Node (3) |
| HTTP dependency edges | **285** |
| Kafka topics | **25** |
| Event subscription edges | **107** |
| Databases | **15** Postgres, one per domain |
| External ERP peers | **9**, in a separate GitHub org |

## Run it

The whole fleet does not need to be running to be useful. `healthcare-infra` ships composable stacks — bring up the seven-service `core` baseline, add `clinical` or `billing` on top, and leave the rest down.
